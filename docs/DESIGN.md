# 오퀴즈 설계서

작성 기준: 2026-10-02. 개인 작업 약 2시간, 외부 API 하나 사용, 와이어프레임부터 구현·검증까지 완료하는 교육 프로젝트.

## 사용자와 목적

짧게 관심 분야의 지식을 확인하고 싶은 사용자가 분야·난이도를 선택하고 영어 객관식 문제 5개를 푼 다음 오답을 복습합니다. 문제 데이터 자체의 신규성보다 짧고 완결된 학습 흐름에 가치를 둡니다.

## 화면 흐름

시작: 분야·난이도 → 로딩 → 문제 1~5 → 결과. 오류 시 시작 화면에서 안내.

문제: 선택 → 정답 확인 → 잠금·피드백 → 다음 문제. 마지막에는 결과 보기.

결과: 문제별 비교 → 오답 다시 풀기 → 복습 결과 또는 새 챌린지.

기록: 최근 최고·평균·목록 → 삭제 확인. 진행 중 홈·기록 이동은 중단 확인.

## 구조 결정

프런트엔드는 HTML·CSS·JavaScript ES 모듈로 작성하고, 화면 계층(app.js)과 데이터 규칙(core.js)을 분리합니다. 공유용 화면은 GitHub Pages에서 제공하며, 같은 화면을 CSS·JavaScript가 내장된 단일 `oquiz.html`로 내려받을 수 있습니다. UI 안내는 한국어, 문제·보기는 영어 원문이며 번역 버튼과 데이터 연결 방식 선택 영역은 표시하지 않습니다.

공유용 화면은 Proxy를 기본으로 사용합니다. 브라우저 → 공개 Cloudflare Worker의 `GET /api/quiz` → Dify Workflow → Open Trivia DB 순서로 문제를 가져옵니다. Dify 앱 키는 Worker의 비밀 환경 변수에만 두고 HTML과 Git에는 포함하지 않습니다. GitHub Pages는 프런트엔드를 제공하고, API는 별도 온라인 게이트웨이가 처리합니다.

Mock(내장 연습 데이터), Direct(브라우저에서 OpenTDB GET), Proxy(Dify 중계)의 세 데이터 어댑터를 교육용 소스와 테스트에 유지합니다. 현재 공유용 홈에서는 Proxy만 실행하며, API 실패를 Mock으로 자동 대체하지 않습니다. 로컬 개발 서버는 정적 파일과 `/api/health`, `/api/quiz`를 제공하고 개발자의 `.env` 설정을 사용합니다. 최근 기록은 브라우저별로 보관하므로 서버 DB는 추가하지 않습니다.

## 데이터

Question: id, question, category, difficulty, correct, answers[{id,text,correct}].

Round: roundId, questions, index, selected, submitted, answers, review.

History: id, date, category, difficulty, mode, correct, total(5), score. 저장 키는 oquiz.history.v1이며 최근 5개만 유지합니다. 복습은 독립 기록으로 저장하지 않습니다. localStorage가 차단되면 현재 창의 메모리에만 기록을 유지합니다.

## 외부 계약

Open Trivia DB 응답의 response_code 0만 성공으로 처리합니다. amount=5, type=multiple, encode=url3986을 고정하며, 전체 분야는 OpenTDB 요청에서 category를 생략합니다. Dify 입력에서는 전체 분야를 `any`로 전달합니다. Proxy는 Dify 실행 성공과 상위 HTTP 상태를 확인한 뒤 유효한 객관식 5문제와 각 보기 4개를 검사합니다.

같은 IP당 5초 호출 제한을 고려하여 브라우저와 게이트웨이에 5.5초 간격을 적용합니다. 게이트웨이의 제한은 실행 인스턴스 단위이므로 공유 IP의 다른 요청까지 통제하지는 못하며, 외부 서비스의 제한 오류도 별도로 표시합니다. 브라우저 타임아웃은 Proxy 45초·Direct 16초이고, 게이트웨이의 Dify 요청 제한은 40초입니다. 자동 무한 재시도는 하지 않습니다.

## 제외 범위

자동 번역, 생성형 AI 해설, 사용자 계정, 전역 랭킹, 실시간 대결, 타이머, 서버 DB, 푸시 알림, 모든 회차의 문제 중복 방지.

## 발표 시연 (약 2분)

1. 영어 문제 안내와 분야·난이도 선택을 보여줍니다.
2. 챌린지를 시작해 일부는 정답, 일부는 오답을 제출합니다.
3. 결과에서 점수와 오답 비교를 보여줍니다.
4. 오답 복습 후 기록이 중복 생성되지 않은 것을 확인합니다.
5. 분야 변경과 실패 시 재시도 흐름을 설명합니다.
